# Architecture rules
- Keep Pipedrive read-only HTTP transport and pure rules under `supabase/functions/_shared`; all three endpoints use one `CrmWriter` so sync and webhook mapping cannot diverge.
- Persist Pipedrive checkpoints only after durable page writes and hydration, and advance the deals watermark only after complete reconciliation; replay remains idempotent after interruption.
- Manual CRM calls require verified admin claims, webhooks require constant-time Basic validation, and scheduled CRM calls require timestamped HMAC validation; unauthenticated sync requests must never bypass authorization.
- CRM conflict targets follow the live composite unique indexes including product kind; never infer constraints from old migrations or alter tables to fit integrations.
- Coupon aliases and ranking exclusions live in the `coupon_people` table, loaded once in the app layout into `src/lib/coupons.ts`; never hardcode people in code so admins can change them without a deploy.
- Batch dates live in the `event_batches` table (Configurações › Lotes), loaded once in the app layout into `src/lib/batchCalendar.ts`; the current batch and each sale's batch come only from those dates in Brasília time, so admins change batches without a deploy.
- Sale→email attribution lives in `src/lib/emailAttribution.ts` (pure, tested) over `ticket_sales.utm_content`; admin overrides live in `email_sale_links`, so guesses never need code changes and the badge totals stay equal to the E-mail marketing channel.
- Integration status, catalog (labels, schedule, credential fields) and plain-language error explanations live in `src/lib/integrationHealth.ts` (pure, tested); the Integrações page and credentials dialog read only from it so status rules never diverge.
- Every dashboard user (any role or event link) sees all events through `can_see_event`; per-event links never limit reads, so nobody sees zeroed data. Logged-person identity for the ranking comes only from `coupon_people.user_id`, auto-linked by `link_coupon_person` (rule mirrored in `src/lib/couponLink.ts`) and overridable by admins (`link_manual`); `team_coupons` is deprecated.
- Account emails share one look in `supabase/functions/_shared/email-brand.tsx`; each template in `_shared/email-templates` only holds its own copy and subjects live in `auth-email-hook`, so a brand change touches one file.
